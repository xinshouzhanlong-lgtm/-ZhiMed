## 0. 一句话定位

这是一个 **FastAPI + SQLite + 原生 JS 的医院智能导诊 Agent（v1 可运行版）**：
患者用语音/文字问「今天哪些科室出诊、某科室在哪、某医生何时坐诊」，系统走
**规则意图识别 → 工具调用 → 模板回答 + grounding 校验** 返回结果；管理端可维护科室信息、
上传医生头像、签发医生自助直链。

**关键认知：它不是大模型 RAG。** LLM 默认关闭（`config/app.json: llm.enabled=false`），
只在可选时做「槽位抽取」和「话术润色」，且润色后必须过 grounding 硬门禁。
真正的工程重心在：**规则编排、数据源容错降级、安全认证、文件/存储工程**。

### 技术栈与依赖（`requirements.txt`）

| 层 | 技术 | 用途 |
|---|---|---|
| Web 框架 | FastAPI 0.115 + uvicorn[standard] | ASGI 路由、依赖注入、静态托管 |
| 数据建模 | Pydantic 2.10 / pydantic-settings | 全项目出入参与内部结构契约 |
| 认证 | PyJWT（HS256）、argon2-cffi | 会话令牌、管理员口令哈希 |
| 外部 HTTP | httpx 0.28（异步） | 预留的 HIS 接口、LLM 调用 |
| 图像处理 | Pillow 11 | 头像校验、裁剪、WebP 编码 |
| 表单上传 | python-multipart | 头像 multipart 上传 |
| 测试 | pytest 8 + pytest-asyncio | 单元 + TestClient 端到端 |
| 前端 | 原生 HTML/CSS/JS（无框架、无构建、无 CDN） | 患者端 / 管理端 / 医生自助三页 |
| 存储 | 标准库 sqlite3（WAL）+ Markdown 文件 | DB 存快照/索引/审计，md 是内容真相源 |

### 2.3 Pydantic v2 数据建模（★ 必需，先读 `schemas.py`）

- `BaseModel`、`Field(default_factory=list/dict)`、`Literal[...]` 限定取值、`StrEnum` 枚举。
- `ConfigDict(frozen=True)` 不可变模型、`populate_by_name=True` + `alias`（如 `pass_` 对应 JSON 的 `pass`）。
- `model_dump()` / `model_copy()` / 嵌套模型组合（`TurnOutput` 内含 `AnswerCard`、`SourceMeta`、`LatencyBreakdown`）。
- 领域枚举即业务状态机：`SourceMode`（四态）、`IntentKind`（九类意图）、`ToolResult.status`、照片 `status(active/superseded/suspended)`。

### 2.4 异步与并发基础（★ 基本即可）

- `asyncio.timeout(...)` 单轮超时；异常 `TimeoutError / asyncio.TimeoutError` 捕获兜底（`loop.py`）。
- 单进程内存态：限流窗口、打转缓存 `_TURN_CACHE`、医生列表 30s 缓存（`hooks.py`、`doctor_api.py`）。
- SQLite 用全局 `threading.Lock` 做单写者，配合 WAL（`state.py`）。

### 2.5 Agent 对话编排（★ 本项目思想核心）

| 概念 | 说明 | 文件 |
|---|---|---|
| 双通道意图识别 | 通道 A 规则直答（`fast`，<10ms，不进 LLM）；通道 B 规则认出意图但缺实体时请 LLM 抽槽（`model`）；都不中 → `fallback` 引导话术，不编造 | `intent.py` |
| 槽位 Slots | `department_id / doctor_id / date / field`，实体必须在给定清单内，模型编造的 id 会被清空 | `intent.py:_model_fill`、`schemas.py` |
| 多轮指代继承 | 近 3 轮会话里的科室/医生，在用户省略主语时只继承、不猜测 | `intent.py`、`state.save_session` |
| 医疗红线优先拦截 | 命中「开药/诊断/是不是癌/挂号」等直接拒绝，不查数据 | `intent.py:REDLINE`、`loop.py` |
| 执行循环预算 | 工具调用上限 3、总超时 6s、token 预算；打转检测（意图+槽位 sha256 指纹连续 2 次相同即打断） | `loop.py` |
| 顶层兜底 | 任何异常不外抛，统一转成「系统繁忙/咨询导医台」，患者端不白屏；异常记入 badcase | `loop.py` |
| grounding 硬门禁 | LLM 润色句里每个事实值必须能在 facts 原文找到（去标点归一化后子串匹配）；不过就**丢弃模型文本、回退模板**，不重试 | `evaluate.py`、`loop._finish` |
| 工具「注册 ≠ 披露 ≠ 授权」 | `register` 持有全集；`disclose` 决定给哪个通道看；`invoke` 经 `pre_tool_use` 钩子决定能否执行，三者物理分离 | `registry.py`、`hooks.py:DISCLOSURE` |
| 钩子链 | `pre_invocation`（限流）、`pre_tool_use`（未披露即拒），任一返回 `allow=False` 短路 | `hooks.py:HookChain` |

### 2.6 数据源容错工程（★ 第二个难点，重点读 `policy.py`）

| 概念 | 说明 | 文件 |
|---|---|---|
| 适配器 Protocol | 所有外部源统一 `health()/fetch()` 契约；适配器只回答「取数成功/失败」，**不做降级决策** | `datasource/base.py` |
| 三种模式 | `off`（模拟不可用）/ `fixture`（本地快照占位）/ `http`（真实对接，本期返回 NOT_CONFIGURED） | `schedule_api.py`、`doctor_api.py` |
| 字段映射层 | HIS 原始字段 → 内部 `ScheduleRow`，字段名变只改 `_map_row/_map_doctor` | `schedule_api.py:FIELD_MAP` |
| 数据源四态 | `api_only`（失败明确「暂无」不静默降级）/ `manual_only` / `api_then_manual`（默认）/ `manual_override`（人工裁决优先，过期自动失效） | `policy.py` |
| 科室级 scope 覆盖 | `sources.json:overrides` 可对单个科室指定模式，覆盖全局 `*`；`resolve_all` 逐科室解析再合并 | `policy.py:resolve_all`、`settings.policy_for` |
| 熔断器 | 连续失败 N 次 → open；open 满 `open_ms` → half_open 试探；成功复位 closed | `datasource/base.py:CircuitBreaker` |
| 降级三态语义 | 成功（rows 非空标来源）/ 空但不降级（`API_UNAVAILABLE`，显示「暂无」）/ 降级（黄条 + 语音声明人工数据） | `policy.py` 注释与 `_ok/_empty` |
| 两源冲突记录 | api 与 manual 同科室 location/医生数不一致 → 落 `data_conflict`，不自动裁决 | `policy._record_conflicts`、`state.py` |
| 过期判断 stale | `now - fetched_at > max_stale_ms` 标过期 | `policy._ok` |
| httpx 错误码映射 | 超时→TIMEOUT、非 2xx→HTTP_5XX、JSON 失败→PARSE_ERROR、未配置→NOT_CONFIGURED | `schedule_api.py` |

### 2.7 安全与认证授权（★ 重点）

| 概念 | 说明 | 文件 |
|---|---|---|
| JWT（HS256） | 登录换 Principal 后签发短期令牌（30min），`Bearer` 携带；验签失败/过期统一 401 不泄露细节 | `auth/principal.py`、`deps.py` |
| argon2id 口令哈希 | 管理员口令只存哈希；5 次失败锁 5 分钟；全程写 `auth_audit` | `auth/password.py` |
| 认证 vs 授权分离 | 认证只产出 `Principal`（你是谁）；授权在 `hooks` 与 `make_photo_grant`（你能做什么） | `deps.py`、`hooks.py` |
| 医生签名直链 magic link | HMAC-SHA256 绑定 `doctor_id|jti|exp`；72h；**上传成功即消费失效**、可撤销；token 放 URL `#fragment`（不进 access log/Referer），换票后前端立即抹除地址栏 | `auth/magic_link.py`、`web/doctor/upload.js` |
| 无状态确认令牌 | HMAC 绑定 `patch_id|after_hash|exp`，exp 由提案创建时间反推，无需额外表；`hmac.compare_digest` 防时序攻击 | `hooks.issue_token/verify_token` |
| 角色与越权 | admin / doctor；医生只能改本人照片（403）；admin 代传必须勾选肖像授权（422）；写工具不对语音通道披露 | `deps.make_photo_grant`、`hooks.DISCLOSURE` |
| 密钥纪律 | JWT/magic_link 密钥只从环境变量读，开发期自动生成落 `.secrets.json`；HIS 凭证绝不落配置 | `settings.py` |
| 文件上传安全 | 魔数嗅探（拒 SVG，不信扩展名/Content-Type）、`MAX_IMAGE_PIXELS` 防解压炸弹、体积上限、正则白名单防路径穿越 | `media/pipeline.py`、`resolve_file` |
| 错误码统一出口 | `E_*` → HTTP 状态映射，未知码一律 400，不回显内部细节 | `core_errors.py` |

### 2.8 存储与文件工程（★ 重点）

| 概念 | 说明 | 文件 |
|---|---|---|
| SQLite + WAL | 标准库 `sqlite3`，`journal_mode=WAL`、`busy_timeout`、`row_factory=Row`；全局锁单写者；事务 commit/rollback | `state.py` |
| 参数化查询 | 全部 `?` 占位，防 SQL 注入 | `state.py` |
| md 是内容真相源 | `departments.md` 存科室事实，DB 只存快照/索引/审计，不反向以 DB 为准 | `md/patch.py`、`datasource/dept_md.py` |
| 原子写 | 写临时文件 → `fsync` → `os.replace` 原子替换（跨平台）；Windows 必须 `O_BINARY`，否则 `\n→\r\n` 导致 hash 不符 | `media/pipeline._atomic_write`、`md/patch._atomic_write` |
| 写后重读校验 | 不信任写入返回值，重读算 sha256 与预期比对，不符则清理/回滚 | `media.store`、`md.commit` |
| 乐观锁 | commit 时 `base_hash` 必须等于当前文件 hash，否则 `E_STALE_BASE` 让用户重新提案 | `md.commit` |
| 文件锁 | `O_EXCL` 排他建锁文件，陈旧锁（超 TTL）可抢占，超时 `E_LOCK_TIMEOUT` | `md/patch.file_lock` |
| 版本快照与回滚 | 提交前存「改之前」快照到 `md_version`；回滚本身也先存一份当前态，保证可撤销 | `md._snapshot`、`md.rollback` |
| diff 预览 | `difflib.unified_diff` 生成人类可读差异，提案不落盘 | `md._diff` |

### 2.9 Pillow 图像处理（○ 用到再查）

- `Image.open` 后 `verify()` 只做完整性校验，**之后对象失效必须重新 open**。
- `ImageOps.exif_transpose` 纠手机拍照方向；`ImageOps.fit` 1:1 居中（人像偏上 0.35）；LANCZOS 重采样；导出 480/192 两档 WebP。
- 内容 sha256 命名去重、`immutable` 长缓存头、旧图置 `superseded` 不删文件。
- 文件：`media/pipeline.py`。

### 2.10 LLM OpenAI 兼容接口（○ 可选，本期默认关）

- httpx POST `/chat/completions`，`response_format=json_object`、`temperature=0`、system/user 消息。
- 要求只输出 JSON，剥离 ``` 代码块；任何失败/关闭返回 None 由调用方降级，绝不抛错。
- 两条用途：槽位抽取（id 必须在清单内）、句式润色（**严禁增删改事实**，且仍过 grounding）。
- 文件：`llm.py`。

### 2.11 原生前端（○ 用到再查）

- vanilla JS：IIFE 封装、DOM API、事件绑定、`escapeHtml` 防 XSS、`createElement` 渲染卡片。
- `fetch` 调 API、`FormData` 上传、`localStorage`（JWT/设备 id）/`sessionStorage`（会话 id）。
- URL `#fragment` 取 magic token 后 `history.replaceState` 抹除。
- Web Speech API：`SpeechRecognition`（zh-CN、interimResults 实时回显、confidence 门禁）+ `speechSynthesis` 朗读回答。
- 文件：`web/kiosk/voice.js`、`web/kiosk/app.js`、`web/admin/app.js`、`web/doctor/upload.js`。

### 2.12 测试（○）

- `pytest` + `pytest-asyncio`、fixture 作用域、`TestClient` 端到端走 HTTP、Pillow 造测试 PNG。
- `conftest.py` 在导入 app 前把 data/db/media 重定向到临时目录，避免污染真实数据。
- `scripts/smoke.py` 用 httpx 对运行中服务跑真实主流程并打印 PASS/FAIL。

## 3. 一次提问的完整链路（端到端走读）

以患者问「**心内科在几楼**」为例：

```
浏览器 voice.js
  └─ POST /api/voice/turn  {text, session_id, device_id}
       └─ main.py: voice_turn
            └─ loop.handle_turn(input, ctx)
                 1. hooks pre_invocation → check_rate 限流（超限直接兜底）
                 2. intent.classify(raw, session)
                      · 红线？否
                      · 规则匹配科室「心内科」→ dept_id；LOCATION_KW「几楼」
                      · 实体齐全 → 返回 (ASK_DEPT_LOCATION, slots, path="fast")
                 3. 打转检测：意图+槽位指纹与上一轮比对
                 4. _execute → registry.invoke("patient_voice","get_department",{name_or_id})
                      · hooks pre_tool_use：该工具是否在 patient_voice 披露白名单
                      · args_model 校验 → runtime._tool_get_department
                      · dept_md.find 精确命中（id→全名→别名）
                 5. 模板拼句「XX在…，诊室是…」，收集 facts
                 6. _finish：llm.polish（若开启）→ evaluate.grounding_check
                      · 通过用润色句；不通过丢弃，回退模板，记 badcase
                 7. 保存会话/查询日志/答案记录 → 返回 TurnOutput(text, cards, source_meta, latency, path)
       ← 浏览器 renderAnswer：气泡 + 科室卡 + 降级黄条 + speechSynthesis 朗读
```

排班查询 `/api/schedule/today` 链路：`main` → `registry.invoke(list_on_duty)` →
`runtime._tool_list_on_duty` → `policy.resolve_all`（四态 + 熔断 + 冲突）→ `decorate` 补医生预览/头像。

管理端改科室地址链路：`POST /api/admin/md/propose`（生成 diff + 确认令牌，不落盘）→
人看 diff → `POST /api/admin/md/commit`（六道门禁 → 原子写 → 重读校验 → 存快照）→ 失败可 `rollback`。
